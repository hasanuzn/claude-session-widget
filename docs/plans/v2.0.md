# Claude Session Widget 2.0 — plan

Status: **approved — phase 0 (spike) in progress.** Decisions are recorded in [Decisions](#decisions).

## Why

1.x is Windows PowerShell + WPF. It works, but it is heavy for a widget that should sit in a corner
all day. Measured on the maintainer's machine (Windows 11, v1.1.0, a few sessions running, 30 s after
start):

| | v1.1.0 |
|---|---|
| Memory (working set) | ~320 MB |
| CPU | ~38 % of one core, continuously |
| `wsl.exe` launches | 5 in 30 s |
| Start-up | 8–15 s |

Most of that comes from the design, not only from PowerShell: every refresh re-reads and re-parses
dozens of JSON files, spawns a new `wsl.exe` per WSL session, and a rotating ✻ animates on a
transparent (layered) window. 2.0 fixes the design and moves to a native, compiled stack, and adds
macOS and Linux.

## Goals

1. **Light.** Budgets below are release blockers, checked by an automated measurement in CI and on
   real machines.
2. **macOS and Linux** next to Windows, from one code base.
3. **Feature parity with 1.1** before 2.0.0 ships (see [Parity checklist](#parity-checklist)).
4. Still **read-only and offline**: no network access at run time.

### Performance budgets

| Metric | Budget |
|---|---|
| Memory, idle, card closed | ≤ 40 MB |
| Memory, card open, 5 sessions | ≤ 60 MB |
| CPU, idle (nothing changing) | ~0 % (no periodic work at all) |
| CPU, while sessions are working | < 1 % of one core on average |
| Start-up to icon visible | < 1 s |
| Installer / download size | < 10 MB |

## Technology

**Rust + [egui](https://github.com/emilk/egui) / eframe** (native UI, no browser engine, MIT/Apache).

| Option | Idle memory (typical) | Why not / why |
|---|---|---|
| **Rust + egui (eframe, glow)** | 30–50 MB | MIT/Apache like the rest of the project, simple, one binary on all three OSes. Kept in reactive mode (repaints only on input or data changes) so it stays idle. **Chosen.** |
| Rust + Slint | 10–30 MB | Lighter and more declarative, but its free (royalty-free) licence requires an attribution in the app; not chosen. |
| Tauri (Rust + web UI) | 50–100 MB on Windows | Uses WebView2/WebKit: too heavy for the budget. |
| C# + Avalonia | 60–100 MB | .NET runtime cost. |
| PowerShell (today) | ~320 MB | — |

Supporting crates (all MIT/Apache): `notify` (file-system events), `serde` / `serde_json`,
`tray-icon` (tray / menu bar), `notify-rust` or the OS toast API (notifications), `auto-launch`
(start with Windows / login item), `directories` (per-OS paths). Avoid heavyweight crates such as
`sysinfo`; check "is process alive" with one OS call per PID.

The memory budget above (≤ 40 MB idle) is set for egui; phase 0 measures it. Use the `glow`
(OpenGL) renderer rather than `wgpu`, keep fonts to one subset, and close the card's viewport when
it is hidden so only the small icon window stays alive.

## Architecture

```
app/                      Cargo workspace (2.0)
  core/                   library, no UI, unit-tested
    status.rs             live process records (~/.claude/sessions/<pid>.json), pid-alive check
    transcript.rs         incremental JSONL reader + plan replay (update_plan / TodoWrite / wrap_up)
    desktop.rs            Claude desktop-app session records (titles, WSL distro, transcript path)
    model.rs              Session { id, name, where, since, steps, current, activity }
  platform/               paths and OS specifics behind one trait
    windows.rs  wsl.rs    WSL bridge (Windows only)
    macos.rs  linux.rs
  ui/                     egui views: bubble, card (accordion rows), settings, i18n
  widget/                 binary: event loop, tray / menu bar, autostart, notifications
  fixtures/               the JSONL / JSON samples from tests/fixtures, shared with core tests
legacy/powershell/        1.x, moved here when 2.0.0 ships; 1.x fixes go to a `v1` branch
```

### Event-driven, not polling

- **Watch, don't scan.** `notify` watches `~/.claude/sessions/`, the desktop app's session-record
  folder and only the transcripts of sessions that are currently busy. Events are debounced
  (~300 ms). With nothing changing, the app does no work.
- **Read only what's new.** Each transcript keeps a byte offset; on change, read from the offset to
  the end and replay just those lines into the cached plan state. First read of a large transcript
  scans backwards for the last task-list call instead of reading the whole file.
- **Running = live `busy` record** (as in 1.1): a record counts only if its PID is alive. Desktop-app
  turn timestamps stay as the fallback for SSH sessions.
- **WSL (Windows only):** file events do not cross into WSL, so one long-lived `wsl.exe -e sh` per
  distro runs a tiny loop that prints changed status records and transcript tails every few seconds
  (`stat` mtimes; no extra tools needed in the distro). Started only while a WSL session exists,
  stopped when none is left.
- **UI only redraws on change.** No continuous animation; a subtle "working" indicator that is
  static or animates only while the card is visible. Blink for unseen finished jobs uses a slow timer
  that stops as soon as they are seen.

## Platform notes

| | Windows | macOS | Linux |
|---|---|---|---|
| Desktop-app sessions | `%LOCALAPPDATA%\Claude-Data\…\claude-code-sessions` | Claude desktop app exists; **record location to be verified on a Mac** | No official desktop app: CLI sessions only |
| WSL sessions | yes (bridge above) | — | — |
| Icon | bottom-right floating bubble + tray | **menu-bar icon** with a dropdown card | tray icon (GNOME needs the AppIndicator extension) + optional floating bubble |
| Not in Alt+Tab / Dock | tool window | `LSUIElement` (no Dock icon) | skip-taskbar hint |
| Start at login | Startup shortcut / registry Run | Login item | `~/.config/autostart/*.desktop` |
| Notifications | Windows toast | User Notifications | freedesktop notifications |
| Package | `.msi` (or small setup `.exe`) + portable `.exe` | universal `.dmg` | `.AppImage` + `.deb` |

## Delivery

- GitHub Actions matrix: `windows-latest`, `macos-14` (universal binary), `ubuntu-22.04`.
- Each `v2.*` tag builds all packages and attaches them to the GitHub Release (same flow as today).
- **Signing:** Windows unsigned at first (SmartScreen warning, as today) — free signing for open
  source via SignPath can be applied for later. macOS: without an Apple Developer account
  ($99/year) users must right-click → Open the first time.
- **Migration on Windows:** the 2.0 installer removes the 1.x PowerShell install and imports
  `%APPDATA%\ClaudeSessionWidget\settings.json`.
- No auto-update in 2.0 (it would need network access); the About/Settings screen links to Releases.

## Parity checklist

- [ ] Running-session detection: local, WSL, SSH (fallback), terminal; stale records ignored
- [ ] Progress bar, current step, step list, latest tool call
- [ ] Icon ↔ card, accordion rows (collapsed: title + bar), drag + remembered position
- [ ] Finished list, blink while unseen, notification
- [ ] Settings: start at login, always on top, on-start view, language (auto/en/tr), transparency,
      notifications, blink, terminal sessions, keep finished (refresh interval goes away: event-driven)
- [ ] Hidden from Alt+Tab / Dock; tray menu (show, settings, always on top, quit)
- [ ] English and Turkish; adding a language = one file
- [ ] Demo mode and off-screen screenshots for the README

## Risks and open questions

- **macOS desktop-app records:** path and fields unknown until checked on a Mac. CLI sessions work
  regardless (same `~/.claude` layout on every OS).
- **Linux tray** support varies by desktop; GNOME needs an extension.
- **Undocumented Claude formats** may change; keep the fixture tests and accept old + new formats.
- **No Mac/Linux hardware here:** CI can build and unit-test, but UI and real-session checks need
  volunteer testers.
- **egui feature gaps** (transparent rounded window, tray integration on Linux, idle repaints) are what phase 0 is for.

## Decisions

Made on 2026-11-10:

1. **UI toolkit:** egui (MIT/Apache) instead of Slint, so no attribution requirement.
2. **macOS signing:** unsigned for now; the README explains right-click → Open. Can be revisited.
3. **1.x:** no further work on the PowerShell version; effort goes to 2.0. 1.x stays available on
   the Releases page until 2.0.0 ships.
4. **Testers for macOS and Linux:** still open — needed before 2.0.0.
